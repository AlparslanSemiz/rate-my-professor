repository. It covers the Admin Web application in this checkout and calls out

## Project Scope

This repository contains a React, TypeScript, and Vite Admin Web single-page
application. The app can run against a backend API when `VITE_API_BASE_URL` is
configured, or against built-in in-memory mock repositories when that value is
empty.

## Configuration

The Admin Web uses Vite environment variables. Values referenced through
`import.meta.env` are part of the frontend build, so configure them before
building the static files that will be deployed.

Do not commit secret values. This repository currently contains `.env`,
`.env.example`, and `.env.demo-local`; `.gitignore` ignores `*.local` but does
not ignore `.env` by name.

### Admin Web Environment Variables

| Variable | Usage | Default or behavior confirmed in repository |
| --- | --- | --- |
| `VITE_API_BASE_URL` | Base URL for the backend API. | Empty in `.env.example`; empty value makes the app use built-in in-memory mock repositories. `.env.demo-local` points to `http://localhost:8080`. |

### GitLab CI/CD Variables

The deploy job uses these custom CI/CD variables:

| Variable | Purpose |
| --- | --- |
| `DEPLOY_HOST` | Required deployment host used for SSH and rsync. The value is supplied by GitLab CI/CD configuration, not by this repository. |
| `DEPLOY_USER` | Required SSH user for deployment. |
| `DEPLOY_SSH_PRIVATE_KEY` | Required private key content written to `~/.ssh/id_ed25519` during the deploy job. Secret. |
| `DEPLOY_PORT` | Optional SSH port. Defaults to `22` when unset. |
| `DEPLOY_PATH` | Remote directory that receives static files. The deploy job defaults this to `/var/www/admin-web`. |

GitLab built-in variables used by the pipeline include:

- `CI_PIPELINE_SOURCE`
- `CI_COMMIT_REF_SLUG`
- `CI_COMMIT_BRANCH`

## Build Instructions

Install dependencies from the lockfile:

```bash
npm ci
```

Run linting:

```bash
npm run lint
```

Run TypeScript project type checking:

```bash
npm run typecheck
```

Run tests:

```bash
npm run test
```

If local tests unexpectedly call a real backend, check whether `.env` sets
`VITE_API_BASE_URL`. To force mock-data mode for a test run:

```bash
VITE_API_BASE_URL= npm run test
```

Run the combined local check command:

```bash
npm run check
```

Build production static files:

```bash
npm run build
```

`npm run build` runs:

```bash
tsc -b && vite build
```

The build output is written to `dist/`.

Start the local Vite development server:

```bash
npm run dev
```

Preview the built production app locally:

```bash
npm run preview
```

No repository file pins the development or preview server port.

## Deployment To The Intended Server Or BW Cloud

The confirmed deployment path is the manual GitLab CI job `web:deploy`.

The job:

1. Runs in the `deploy` stage using `alpine:3.22`.
2. Requires the packaged artifact from `web:package`.
3. Installs `openssh-client` and `rsync`.
4. Verifies that `DEPLOY_HOST`, `DEPLOY_USER`, and
   `DEPLOY_SSH_PRIVATE_KEY` are present.
5. Writes the private key to `~/.ssh/id_ed25519`.
6. Adds the remote host key with `ssh-keyscan`.
7. Extracts `admin-web-dist.tar.gz` into a local `deploy/` directory.
8. Creates the remote deployment directory.
9. Synchronizes `deploy/dist/` to `$DEPLOY_USER@$DEPLOY_HOST:$DEPLOY_PATH/`
   with `rsync -az`.

`DEPLOY_PATH` defaults to:

```text
/var/www/admin-web
```

The deploy job is available only on the `main` branch and is manual. It is
marked `allow_failure: true`.

## CI/CD Pipeline Usage

The GitLab pipeline is defined in `.gitlab-ci.yml`.

Pipeline source:

- Push pipelines only, because `workflow.rules` allow
  `CI_PIPELINE_SOURCE == "push"`.

Stages:

- `check`
- `test`
- `build`
- `package`
- `deploy`

Jobs:

| Job | When it runs | What it does |
| --- | --- | --- |
| `web:check` | Push pipelines | Runs `npm run lint` and `npm run typecheck`. |
| `web:test` | Push pipelines | Runs `npm run test`. |
| `web:build` | Push pipelines | Runs `npm run build` and publishes `dist/` as a one-week artifact. |
| `web:package` | `main` branch push pipelines | Runs `npm run build`, creates `admin-web-dist.tar.gz`, and publishes it as a one-month artifact. |
| `web:deploy` | Manual job on `main` branch push pipelines | Extracts the packaged artifact and rsyncs `dist/` to the configured deployment host. |

The shared Node job template:

- uses `node:24-alpine`
- caches `.npm/` with key `npm-${CI_COMMIT_REF_SLUG}`
- runs `npm ci --cache .npm --prefer-offline`

The deploy job does not build or run a Docker image. It deploys static frontend
files.

## Basic Troubleshooting

| Symptom | Confirmed cause or check |
| --- | --- |
| App shows mock data instead of backend data | `VITE_API_BASE_URL` is empty, so the app uses in-memory repositories. Set `VITE_API_BASE_URL` before building if real backend data is required. |
| Frontend API requests fail | Check that `VITE_API_BASE_URL` points to the intended backend base URL and that the backend implements the API paths used by `src/api/*Service.ts`. |
| `npm run test` tries to reach a real backend | A local `.env` value for `VITE_API_BASE_URL` is being loaded. Run tests with `VITE_API_BASE_URL=` to force mock-data mode, or adjust the local environment. |
| Changes to `VITE_API_BASE_URL` do not affect deployed static files | Rebuild and redeploy the app. The source reads `import.meta.env.VITE_API_BASE_URL` during the Vite build. |
| Direct navigation to `/login` returns 404 on the deployed host | The static web server likely lacks an SPA fallback to `index.html`. Web server configuration is not included in this repository. |
| `web:deploy` fails before rsync | Confirm `DEPLOY_HOST`, `DEPLOY_USER`, and `DEPLOY_SSH_PRIVATE_KEY` are configured in GitLab CI/CD variables. |
| `web:deploy` cannot connect over SSH | Check `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PORT`, remote host key access, and the private key permissions configured by the CI job. |
| Files deploy to the wrong directory | Check `DEPLOY_PATH`; the job defaults it to `/var/www/admin-web`. |
| CI build fails | Run `npm ci`, `npm run lint`, `npm run typecheck`, `npm run test`, and `npm run build` locally to reproduce the failing step. |
